#### **4. Subredes y sus Características (17:31 - 20:21)** ✅

La solución planteada es la creación de **subredes**, que consiste en dividir una gran red *(o un gran dominio de broadcast),* en grupos  más pequeños  (*en áreas lógicas más pequeñas y jerárquicas.*)

<aside>
💡

Los encargados de dividir los dominios de broadcast son los routers, mientras que los switches conectan fisciamente los dispositvios 

</aside>

Esto reduce el tamaño de los dominios de broadcast, optimiza el tráfico y facilita la implementación de reglas de seguridad (por ejemplo, definir qué subredes pueden acceder a Internet y cuáles no). Estas subredes son administradas internamente y son invisibles desde el exterior

CARACTERISTICAS:

1. Jerarquicas
    1. Introducen un nivel adicional de jerarquía en las direcciones IP, más allá de las partes Host y Red.
2. Las Asigna el Administrador de Red:
    1. Creadas por el administrador de red a partir de la dirección de red proporcionada por el proveedor.
    • Conocido como plan o esquema de direccionamiento IP.
3. Visibilidad Interna:
    1. Solo son visibles dentro de la organización; desde fuera, solo se ve la red completa.
4. Modificación de Máscaras de Subred:
    1. Se ajustan las máscaras de subred para definir y delimitar las subredes.

Ventajas:

1. Control del Tráfico entre Áreas de la Empresa:
    1. Permite dividir el direccionamiento según áreas de la empresa para controlar el tráfico y mejorar la seguridad.
    • Evita la necesidad de más routers, lo que sería más costoso.
2. Reducción de Dominios de Broadcast:
    1. Evita un único dominio de broadcast grande para toda la red.
    • Se crean varios dominios más pequeños, uno por cada subred.
3. Facilita Implementación de Seguridad:
    1. Posibilita la configuración de listas de control de accesos (ACL) para cada subred, mejorando la seguridad

#### **10. CANTIDAD MAXIMA DE SUBREDES (1:11:09 - 1:17:08)**✅

Cuanto es el maximo de bits que se pueden pedir prestados en una red clase C? porque?

- **Límite de bits a pedir prestados:** En una red Clase C el máximo de bits prestados es 6. Esto deja 2 bits para la porción de host, que es el mínimo necesario para tener al menos 2 IPs válidas, típicamente usado en enlaces WAN (punto a punto).

La razón fundamental es que **siempre debe quedar un mínimo de 2 bits disponibles para la porción de host**. 

En una red de Clase C, solamente el cuarto byte (8 bits) está destinado a los hosts; por lo tanto, si se toman prestados 6 bits para crear subredes, restan exactamente 2 bits para identificar a los hosts.

![{752909DB-1687-41F8-8697-2315AA1B4096}.png](752909DB-1687-41F8-8697-2315AA1B4096.png)

Con estos 2 bits restantes se obtienen 4 combinaciones posibles ($2^2$). Al restar las dos direcciones que siempre están reservadas (la primera para la dirección de la subred y la última para el broadcast), **quedan exactamente 2 direcciones IP válidas** que pueden asignarse a dispositivos. Esta cantidad mínima suele utilizarse para enlaces punto a punto (conexiones WAN entre dos routers).

---

Si se intentara pedir prestados 7 bits, **solo quedaría 1 bit para los hosts**, lo que generaría apenas 2 combinaciones. Dado que obligatoriamente una se utilizaría para identificar la subred (valor 0) y la otra para el broadcast (valor 1), **no quedaría ninguna dirección IP válida disponible** para asignar a los equipos de los usuarios o routers, haciendo que esa subred no tenga utilidad.

![{B5DE88A0-8C1F-45FD-8423-41D60E9F8B3F}.png](B5DE88A0-8C1F-45FD-8423-41D60E9F8B3F.png)

- Cantidad de direcciones en una subred
    
    al crear subredes, se aprovecha mejor la cantidad de dircicones ip validas?
    
    No, ocurre exactamente lo contrario: al crear subredes **no se aprovecha mejor la cantidad total, sino que se pierden direcciones IP válidas**.
    
    Esto sucede porque matemáticamente, por cada nueva subred que se crea, **obligatoriamente se deben restar dos direcciones que quedan reservadas**: la primera (que identifica a la dirección de la subred en sí) y la última (que se utiliza como dirección de difusión o *broadcast*). Como estas dos direcciones no pueden asignarse a ningún dispositivo o puesto de trabajo, el total neto de direcciones utilizables en la organización disminuye al ir fragmentando la red.
    
    ---
    
    caso practico: dada la direccion ip 195.34.20.0/24 se decidenc rear 12 subredes
    
    cuantas direcciones ip validas se disponra en c/u de las subredes?
    
    14, porque me quedan  4bits para host → 2^2-2=14
    
    cuantas direccion ip validas se dipondra en total en la organizacion
    
    16*14, porque 16 va ser el total de subredes si se toman 4 bits y en cada subred vamos a tener 14
    
    cuantas direcciones se pirden en total?
    
    El profesor lo demostró con un caso práctico durante la clase. Si una organización decide tomar 4 bits prestados y crea 16 subredes, forzosamente perderá 2 direcciones IP por cada una de esas nuevas áreas. Al multiplicar 16 subredes por 2 direcciones reservadas en cada una, el resultado es que **se pierden 32 direcciones IP en total** de las que originalmente se disponían.
    
    Por lo tanto, aunque se reduce el número neto de direcciones utilizables, la decisión de crear subredes no se toma para ahorrar IPs, sino por sus otras ventajas fundamentales: **reducir los grandes dominios de broadcast, organizar las áreas de la empresa, optimizar el flujo de tráfico y mejorar la seguridad** de la red.
    

#### **11. Obtener la Subred a partir de una IP (1:17:09 - 1:20:49)** ✅

Resumen

Para obtener la subred a partir de una dirección IP, se sigue un proceso en tres pasos: escribir la dirección IP y la máscara en formato booleano, considerando la clase y los bits prestados en el prefijo, y realizar una
operación AND booleana. Este método es similar al utilizado para redes, pero la máscara tiene más bits activados.
Al analizar una dirección IP, como por ejemplo 200.4.6.80:

1. Para determinar si es una dirección de host válida, se necesita la máscara. En subredes, la dirección IP y la máscara son inseparables.
2. Para identificar si es una dirección de subred, se examina el último byte después de aplicar la máscara.
Ejemplos:
    1. Con una máscara /26, el último byte con dos bits prestados sería 0 1 | 0 1 0 0 0 0, siendo una dirección de host válida.
    2. Con una máscara /28, el último byte con cuatro bits prestados sería 0 1 0 1 | 0 0 0 0, indicando una dirección de subred debido a que todos los bits del host son 0. Si todos fueran 1, también sería una dirección de subred o de broadcast

---

detallado clase:

El profesor explicó este procedimiento detalladamente utilizando como ejemplo la dirección IP **`197.4.8.168/27`**. El paso a paso es el siguiente:

1. **Identificar la máscara:** Al ser una IP de Clase C → 197. (cuya máscara por defecto es `/24`), el prefijo `/27` permite deducir que se tomaron 3 bits prestados para la porción de subred.
2. **Convertir a binario:** Se transforma el byte relevante de la dirección IP y de la máscara a formato binario para poder compararlos.
    - El valor `168` de la IP en binario es: `10101000`.
    - El último byte de la máscara `/27` en binario es: `11100000`,(el resto de bytes son 1)
    
    ![{F1A853CC-CB38-4F72-93B0-AAC78C359882}.png](F1A853CC-CB38-4F72-93B0-AAC78C359882.png)
    
3. **Ejecutar el cálculo AND:** Se compara matemáticamente bit por bit de manera vertical (donde `1x1=1`, `0x1=0`, etc.).
    - En la porción de red y subred (donde la máscara tiene unos), el valor de los bits de la IP original simplemente se copia.
    - En la porción de host (donde la máscara está conformada por ceros), **todos los bits se anulan**, dando siempre cero sin importar qué valor tenían originalmente en la IP.
    - El resultado de realizar la operación AND entre `10101000` y `11100000` da como resultado binario **`10100000`**.
    
    ![{F2BF7C8B-4F5A-4F41-A922-52342DC26A10}.png](F2BF7C8B-4F5A-4F41-A922-52342DC26A10.png)
    
4. **Obtener el resultado final:** Al convertir el resultado binario `10100000` nuevamente a sistema decimal, se obtiene el valor `160`. De esta forma, se descubre que la IP `197.4.8.168/27` pertenece exactamente a la **dirección de subred `197.4.8.160`**.

💡

**Importancia de este cálculo:** El profesor destaca que saber hacer esto es fundamental para un administrador, ya que ayuda a evitar confusiones operativas, impidiendo que por error se le asigne a un dispositivo una dirección IP que en realidad pertenece al rango de otra subred distinta.

</aside>
